# 知膳 NutriMind · AI 营养分析师

> 赛道六「AI 健康与生活服务」参赛作品 —— 用 AI 把每一餐拆解成看得懂、改得动的营养数据。

知膳（NutriMind）是一套面向普通人的 AI 营养分析 Web 应用。用户只需要用日常口语描述自己吃了什么（例如「一碗牛肉面加个煎蛋」），系统即可自动拆解食材、估算克数与营养，给出可解释的餐食评分与改进建议，并长期沉淀为个人营养档案、趋势报告与 AI 营养师对话。

- 双端适配：桌面端 Web（固定侧栏）与移动端 Web（底部标签栏），同一套代码。
- 双引擎 AI：配置大模型 Key 时调用 LLM（含图片识别、流式对话）；未配置时自动使用内置的本地营养解析引擎，保证离线可演示、不依赖网络。
- 纯前端架构：无需后端与数据库，数据保存在浏览器 localStorage，打开即用。

## 在线体验

- 本地启动后访问 `http://localhost:5173/`（落地页），应用入口为 `/#/app`。
- 无需注册登录；「健康档案」页可一键重置示例数据，便于评审快速体验完整流程。

## 功能一览

| 模块 | 说明 |
| --- | --- |
| 落地页 | 产品价值、AI 分析演示卡、科学依据与免责声明 |
| 今日概览 | 当日热量环、三大宏量进度、AI 今日洞察、按餐次记录、7 日趋势 |
| AI 营养分析 | 自然语言 / 图片输入 → 食材拆解 → 营养明细（克数可实时调整重算）→ 评分 → 建议 → 一键加入今日饮食 |
| AI 营养师 | 结合个人档案与今日摄入的多轮对话，支持 SSE 流式输出与快捷提问 |
| 饮食记录 | 按日期与餐次管理摄入，支持食物库搜索、份量与单位换算 |
| 营养报告 | 7 / 30 天趋势、宏量结构、营养素达成度、AI 周报 |
| 健康档案 | 基础信息、活动量、目标、过敏偏好；实时计算 BMR / TDEE / 每日目标；AI 引擎设置 |

## 技术架构

```
React 18 + TypeScript 5 + Vite 5
├── 路由      react-router-dom 6（HashRouter，静态托管刷新不 404）
├── 样式      Tailwind CSS 3.4 + 自定义设计令牌（暖米白 / 深墨绿 / 青柠 / 珊瑚）
├── 图标      lucide-react
├── 状态      React Context（AppContext）+ localStorage 持久化
└── AI        OpenAI 兼容 /chat/completions（可选）+ 本地规则引擎（兜底）
```

- **AI 分析链路**：自然语言 → 中文口语分词 → 食物库最长匹配（含别名、修饰词）→ 份量解析（克 / ml / 中文数字 / 单位）→ 营养换算 → 可解释评分（热量占比、蛋白密度、纤维、钠、糖）→ 规则化点评。配置 LLM 后由模型直接产出结构化 JSON（食材、摘要、亮点、建议），失败自动降级到本地引擎。
- **AI 对话链路**：拼接用户档案、每日目标与今日摄入作为上下文，调用 OpenAI 兼容接口并按 SSE 增量渲染；异常时使用本地关键词规则回复。
- **图片识别**：上传餐食图片后以 dataURL 形式传入多模态模型（需模型支持 vision），由模型识别食材与份量。
- **营养算法**：Mifflin-St Jeor 基础代谢、活动系数 TDEE、按目标调整热量（减脂 ×0.82、增肌 ×1.12，且不低于 BMR）、宏量营养素目标、BMI 分级与餐次热量占比。

## 安装与运行

要求：Node.js ≥ 18，npm ≥ 9。

```bash
# 1. 安装依赖
npm install

# 2. （可选）配置 AI 引擎
cp .env.example .env
# 编辑 .env，填写 VITE_AI_BASE_URL / VITE_AI_API_KEY / VITE_AI_MODEL

# 3. 启动开发服务器
npm run dev
# 浏览器打开 http://localhost:5173/

# 4. 生产构建与本地预览
npm run build
npm run preview
```

> 也可以在应用内「健康档案 → AI 引擎设置」中直接填写接口地址、Key 与模型，配置会保存在本地浏览器，无需重启。

## 环境变量说明

| 变量 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| `VITE_AI_BASE_URL` | 否 | `https://api.deepseek.com/v1` | OpenAI 兼容接口基础地址，不含 `/chat/completions` |
| `VITE_AI_API_KEY` | 否 | `sk-...` | 接口密钥 |
| `VITE_AI_MODEL` | 否 | `deepseek-chat` | 模型名称；图片识别需多模态模型 |

未配置时应用自动使用本地引擎，所有页面功能完整可用。

> 安全提示：`VITE_` 前缀变量会被打包进前端产物。本方案面向演示，正式部署建议通过服务端代理转发密钥，切勿将真实 Key 提交到 Git。

- **环境配置**：提供 `.env.example` 与依赖清单（`package.json`）。
- **Git 记录**：保留分阶段提交历史。
