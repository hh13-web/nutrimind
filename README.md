# 知膳 NutriMind · AI 营养分析师

> 赛道六「AI 健康与生活服务」参赛作品 —— 用 AI 把每一餐拆解成看得懂、改得动的营养数据。

知膳（NutriMind）是一套面向普通人的 AI 营养分析 Web 应用。用户只需要用日常口语描述自己吃了什么（例如「一碗牛肉面加个煎蛋」），系统即可自动拆解食材、估算克数与营养，给出可解释的餐食评分与改进建议，并长期沉淀为个人营养档案、趋势报告与 AI 营养师对话。

- 双端适配：桌面端 Web（固定侧栏）与移动端 Web（底部标签栏），同一套代码。
- 账号体系：邮箱 + 密码注册登录，每个账号拥有独立的健康档案、饮食记录与对话数据；支持游客模式零门槛体验。
- 双引擎 AI：服务端配置大模型后调用 LLM（流式对话）；未配置时自动使用内置的本地营养解析引擎，保证离线可演示。
- 前后端一体：Node.js 服务端负责账号认证、AI 代理与静态托管，API Key 只在服务端环境变量中读取。

## 功能一览

| 模块 | 说明 |
| --- | --- |
| 登录注册 | 邮箱 + 密码登录/注册，scrypt 加盐存储密码，HMAC 签名令牌；游客模式可浏览，使用 AI 功能时弹窗引导登录；独立退出登录界面 |
| 落地页 | 产品价值、AI 分析演示卡、科学依据与免责声明；「登录」进入登录页，「免费开始」以游客身份进入 |
| 今日概览 | 当日热量环、三大宏量进度、AI 今日洞察、按餐次记录、7 日趋势（数据来自本人真实记录） |
| 餐食分析 | 自然语言输入 → 食材拆解 → 营养明细（克数可实时调整重算）→ 评分 → 建议 → 一键加入今日饮食 |
| 营养问答 | 结合个人档案与今日摄入的多轮对话，支持 SSE 流式输出与快捷提问；会严格区分早餐/午餐/晚餐 |
| 饮食记录 | 按日期与餐次管理摄入，支持食物库搜索、份量与单位换算 |
| 营养报告 | 7 / 30 天趋势、宏量结构、营养素达成度、AI 周报 |
| 健康档案 | 用户填写年龄、身高、体重、活动量、目标与过敏偏好；草稿态编辑，点击「保存档案」才写入并给出反馈；保存后全站目标即时更新 |

## 技术架构

```
React 18 + TypeScript 5 + Vite 5
├── 路由      react-router-dom 6（HashRouter，静态托管刷新不 404）
├── 样式      Tailwind CSS 3.4 + 自定义设计令牌（暖米白 / 深墨绿 / 青柠 / 珊瑚）
├── 图标      lucide-react
├── 状态      React Context（AuthContext + AppContext）+ 按账号隔离的 localStorage 持久化
├── 服务端    Node.js 20 原生 http 模块（账号认证 / AI 代理 / 静态托管，无第三方依赖）
└── AI        OpenAI 兼容 /chat/completions（服务端代理）+ 本地规则引擎（兜底）
```

- **认证链路**：注册/登录由服务端校验，密码使用 `scrypt` 加盐哈希；令牌为 HMAC-SHA256 签名，默认 7 天有效。前端只保存令牌与用户公开信息。
- **AI 代理链路**：前端请求 `/api/ai/chat`，服务端注入 `AI_API_KEY` 后转发到 OpenAI 兼容接口，支持 SSE 流式透传；浏览器永远接触不到密钥。
- **AI 分析链路**：自然语言 → 中文口语分词 → 食物库最长匹配（含别名、修饰词）→ 份量解析（克 / ml / 中文数字 / 单位）→ 营养换算 → 可解释评分（热量占比、蛋白密度、纤维、钠、糖）→ 规则化点评。配置 LLM 后由模型直接产出结构化 JSON，失败自动降级到本地引擎。
- **AI 对话链路**：拼接用户档案、每日目标与今日摄入作为上下文，按「用户点名的餐次」优先回答，再调用服务端流式接口；异常时使用本地关键词规则回复。
- **图片识别**：当前文本模型不支持图片识别，如需图片分析需切换多模态（vision）模型。
- **营养算法**：Mifflin-St Jeor 基础代谢、活动系数 TDEE、按目标调整热量（减脂 ×0.82、增肌 ×1.12，且不低于 BMR）、宏量营养素目标、BMI 分级与餐次热量占比。

## 安装与运行

要求：Node.js ≥ 20，npm ≥ 9。

```bash
# 1. 安装依赖
npm install

# 2. 构建前端
npm run build

# 3. （可选）配置服务端环境变量
cp .env.example .env
# 编辑 .env：AUTH_SECRET / AI_BASE_URL / AI_API_KEY / AI_MODEL
# 服务不会自动读取 .env，可用 set -a && source .env && set +a 或部署平台的环境变量

# 4. 启动服务
npm start
# 浏览器打开 http://localhost:8000/
```

开发模式（前端热更新，API 代理到 8000 端口）：

```bash
# 终端 A：启动后端
npm run dev:server

# 终端 B：启动 Vite
npm run dev
# 浏览器打开 http://localhost:5173/
```

## 环境变量说明

全部变量只在服务端读取，不会打包进前端产物。

| 变量 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| `PORT` | 否 | `8000` | 服务监听端口 |
| `DATA_DIR` | 否 | `./data` | 账号数据目录，`users.json` 写入此处 |
| `AUTH_SECRET` | 是（生产） | 随机长字符串 | 登录令牌 HMAC 签名密钥 |
| `AI_BASE_URL` | 否 | `https://api-inference.modelscope.cn/v1` | OpenAI 兼容接口基础地址，不含 `/chat/completions` |
| `AI_API_KEY` | 否 | `ms-...` | 接口密钥，仅在服务端使用 |
| `AI_MODEL` | 否 | `Qwen/Qwen3.8-Flash-Next` | 模型名称；若需图片识别请改用支持 vision 的多模态模型 |

未配置 `AI_*` 时应用自动使用本地引擎，所有页面功能完整可用。

> 安全提示：AI Key 与登录密钥只通过服务端环境变量注入，前端代码与构建产物中不包含任何密钥。`data/` 目录已加入 `.gitignore`，请勿提交真实用户数据。
